# ADR-0001：建立独立的 idp-platform-go 能力库

状态：已接受

日期：2026-08-24

## 背景

TMS 与 Parcel 需要单据编号等跨应用平台能力（已书面确认用例：运输任务编号、对账单号）。bento-go ADR-0010 确立平台能力不进框架；Python 侧已有生产验证的 `idp-platform` 可作参照。维护者确认双消费者必用并要求立即建库，不等待"真实重复出现"。

## 决定

- 建立独立仓库与 Go module `go.idp.xyz/idp-platform-go`，参考 Python `idp-platform` 的能力划分。
- 库拥有能力代码与自己技术表的不可变迁移资产；消费者拥有数据、迁移执行、权限和历史。
- 编号原语（模板 DSL、加扰、校验位、序列分配）归本库（bento-go ADR-0011 同日撤回框架 `v0.2` 路线）。
- 切片一 numbering，切片二 options；本库对框架是普通消费者，不依赖其 `internal`/`testkit`。
- TMS 与 Parcel 的业务语言不进入本库；单据类型与选项组由消费者注册。

## 后果

- 编号能力单一归属、独立发布节奏，不受框架双消费者门禁约束。
- 在真实重复出现前预付了库治理成本（兼容性、版本、发布），维护者已接受该代价。
- 消费者多一个依赖坐标；框架保持 `v0.1` 极简范围不受扰动。

## 考虑过的替代方案

- 能力进框架：被 bento-go ADR-0010/0011 否决，框架公共面不可控。
- 各消费者自实现：维护者否决——双消费者必用共享库，且 DSL/加扰会分叉出不兼容方言。
- 等真实重复出现再立库：维护者否决时限；立即立库以统一起点。
